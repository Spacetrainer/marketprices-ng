- [Tags/pins] P9.1 enumerates the tables that may carry an anon SELECT policy ("only on": sections, commodities, units, collection_sites, price_observations, basket_snapshots where is_complete, articles where published). 0014_tags.sql amends that list by THREE, consciously: `tags` and `article_tags` because /tag/[slug] is a public page rendered as a join-table query (§13 placement map) and neither table is readable by a signed-out visitor without it; `homepage_pins` because getSectionArticles() applies pins before falling back to recency and runs on the public homepage under ISR. The homepage_pins policy is scoped to `expires_at > now()` so an expired pin is unreachable rather than merely unrendered; the other two are unscoped, since a tag is a slug and a display name and a join row exposes only that some article id carries some tag (the article itself stays behind articles' published filter). The alternative considered for homepage_pins — routing the homepage query through a service-role client — was rejected: it makes every homepage render depend on a privileged connection for one small table, to avoid exposing a uuid that cannot be resolved to a person because profiles is not anon-readable. Revisit if P9.1's list is ever restated: it should be amended to name these three, or these policies should be narrowed.
- [Articles] articles.type shipped in 0013 with two values ('standard', 'video'); §1.2 and §1.3 both specify three, the third being 'data' (card treatment "chart or table preview instead of a photo", body "rich text + embedded price widget"). 0013 was already applied when this was found, so the fix is 0015_article_type_data.sql — a widening of the existing `articles_type_check` constraint, reusing the same constraint name — rather than an edit to 0013. No exemption was created for 'data' articles: header_media_id stays NOT NULL, because §1.3's "instead of a photo" describes the card, while §1.4's "every content item carries a designed graphical header, rendered from a template against bound data" is unqualified and a rendered chart is precisely that.
- [Homepage] NOTED GAP, blocks Stage 12 — no table anywhere holds the hero. §1.5 says `hero_lead`, `hero_secondary_1` and `hero_secondary_2` are manually curated with a fallback to most-recent-across-all-sections after 24h.
